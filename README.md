# Shell:B Translations

[![Validate](https://github.com/ShellB-App/Shell-B-Translations/actions/workflows/validate.yml/badge.svg)](https://github.com/ShellB-App/Shell-B-Translations/actions/workflows/validate.yml) [![MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

Interface languages for [Shell:B](https://github.com/ShellB-App/Shell-B), the local-first AI workspace.
Part of the family with [Shell-B-Themes](https://github.com/ShellB-App/Shell-B-Themes), [Shell-B-Screensavers](https://github.com/ShellB-App/Shell-B-Screensavers) and [Shell-B-Skills](https://github.com/ShellB-App/Shell-B-Skills).

Shell:B's interface is written in English, and every string it shows goes through `t()`. A catalogue is one JSON
file mapping those English strings to a language; a string with no entry stays in English, so a half-finished
language is still usable. `keys.json` lists every string the current Shell:B uses (exported from its UI source), so
a catalogue can be checked for coverage and for entries that went stale after an update.

## How a language reaches Shell:B

French ships inside Shell:B (`ui/src/i18n/fr.json` in the main repository, where a test fails on any interface string
without an entry). Every other language is loaded at run time: Shell:B serves the catalogue from a checkout of this
repository next to it, or fetches it from here on GitHub, and keeps a copy in the browser. Pick it in Settings →
General → Language; Settings → Languages shows coverage per language.

**Drafts.** Languages marked *draft* in the table are machine-made starter sets (the most common buttons and labels,
drafted with AI and `scripts/translate_ollama.py`), not yet read through by a speaker. `scripts/verify.py` only runs
automatic checks on them (placeholders kept, nothing left in English, a few glossary terms) and links each flagged
string to a dictionary; it doesn't prove a translation right. Corrections from speakers are very welcome, and a
language loses the *draft* mark once someone has reviewed it.

## Add or improve a language

1. Copy `locales/fr.json` to `locales/<code>.json` (a BCP 47 code: `de`, `es`, `pt-BR`, `zh-Hant`) and translate the
   values. Keep the keys exactly as they are: they are the English strings Shell:B looks up. Keep placeholders such
   as `{name}` or `{count}` in the translation. Remove entries you can't translate rather than leaving English in
   them. `keys.json` is the full list to work through; `fr.json` shows the tone (short, direct, no corporate voice).
2. Add your language to `locales.json`: its own name (`Deutsch`, not `German`), `author`, optional `authorUrl`,
   `license` (an SPDX id), `version`.
3. Run `python3 -I scripts/validate.py`. It checks the JSON, the placeholders, reports coverage and stale entries,
   and rebuilds `index.json` and the table above.
4. Open a pull request (the template has the checklist), or a *Submit a translation* issue with the file attached.

Translations that the test in Shell:B can enforce need an entry for every string in `keys.json`; partial ones are
welcome here and reach Shell:B at run time as soon as they're merged.
